# 企业就绪度评估

评估日期：2026-09-18

## 结论

本项目达到“单企业、单实例、低并发、内网部署的部门级试点”水平，能够作为企业版第一阶段交付物；它不是开箱即用的集团级生产平台，也不应承载机床控制或无人审核的维修决策。

## 当前基本满足

| 能力 | 当前状态 |
| --- | --- |
| 真实业务边界 | 围绕机型、报警、备件、维修案例、受控文档和售后会话设计，明确不控制设备 |
| 数据隔离 | 会话按用户校验所有权；管理员可审计但普通用户不能访问他人会话 |
| 权限与账号 | 四类角色、账号启停、持久化登录锁定、管理员解锁、密码变更后旧令牌失效 |
| 知识治理 | 上传、解析、候选提取、人工审核、发布、驳回、废止全流程 |
| 操作留痕 | 登录成功/失败、锁定、账号管理、问答、审核和反馈写入数据库审计表 |
| 数据安全 | 生产密钥强校验、数据库不暴露宿主机端口、上传大小限制、文档唯一约束、安全响应头 |
| 可运维性 | Alembic 迁移、存活/就绪探针、请求与审计关联、Docker 健康依赖、自动化测试与 CI |
| 低并发能力 | 单 API 实例和同步文档解析适合小型售后团队的日常问答与少量资料导入 |

## 部分满足

| 能力 | 不足与建议 |
| --- | --- |
| 数据不泄露 | 默认不调用外部大模型，但尚无 DLP、字段脱敏和下载水印；接外部模型前必须增加出站审查 |
| 数据不误删 | 业务接口没有批量硬删除，但数据库、图数据库和文件目录仍需备份与恢复演练 |
| 审计合规 | 已留痕但审计表并非不可篡改；高合规场景应同步到独立日志平台或 WORM 存储 |
| 文件安全 | 有扩展名、大小、空文件和重复校验，但没有杀毒、沙箱、压缩炸弹检测和隔离区 |
| 可观测性 | 有健康探针和请求标识，但没有指标、集中日志、告警规则和跨服务链路追踪 |
| 身份体系 | 有本地账号但没有 SSO、MFA、企业目录同步和细粒度数据权限 |
| 性能 | 低并发可用，但 OCR/大型 PDF 在 API 进程同步解析，可能阻塞请求并触发超时 |

## 正式生产前必须补齐

1. 用真实受控手册、备件主数据和脱敏工单替换全部演示流程数据，完成业务盲测和责任人签字。
2. 部署 HTTPS，接入企业 SSO/MFA，并把浏览器令牌迁移到符合企业策略的安全会话方案。
3. 对上传文件执行恶意文件扫描、隔离和内容脱敏；大型解析改为持久化后台任务。
4. 将 Neo4j 导入账号与应用只读账号分离，限制数据库网络和最小权限。
5. 建立 PostgreSQL、Neo4j、原始资料的一致性备份、恢复演练和保留周期。
6. 将审计日志发送到独立日志平台，配置异常登录、连续拒答、解析失败和存储容量告警。
7. 完成依赖漏洞扫描、并发压测、故障演练，并明确单实例容量上限和升级方案。

## 不在当前目标内

- 多企业多租户平台、跨地域双活和大规模高并发。
- PLC/CNC 实时采集、远程控制、自动修改参数或绕过安全互锁。
- 由系统独立承担维修结论、采购审批或事故责任。
