# 项目复审报告

复审日期：2026-09-18

## 本轮发现并修复

1. 未知故障在匹配不到知识时曾退回产品参数，容易让用户误以为系统给出了处理结论；现已改为明确拒答。
2. 报警排查与备件查询的模糊匹配会串线；现已拆分意图，具体备件问题默认只返回一个最佳匹配，宽泛列表问题才返回多个结果。
3. 问答未使用序列号字段；现已接入请求、界面和缺失信息提示，但不把序列号明文写入审计详情。
4. 问答未关联备件和历史案例；现已补充来源类型、核对条件和相似案例关闭验证。
5. 无效机型仍会继续检索；现改为立即拒答并提示补充产品主数据。
6. 候选知识可在来源文档发布前单独发布；现已阻止，并让文档驳回/废止状态联动到候选知识。
7. 上传允许空文件、未知机型和非 HTTP 来源网址；现已增加校验，并阻止相同名称与版本重复导入。
8. 超长单段文档不会按上限切块，标题还可能错配；现已支持带重叠的长段切分并保留正确标题。
9. 登录页预填演示密码；现已清空密码字段。
10. 缓存用户数据损坏会导致前端启动失败；现已安全清理损坏的本地登录状态。
11. 前端隐藏管理菜单但未阻止直接访问管理路由；现已增加角色路由守卫，后端权限校验继续作为最终边界。
12. 修改密码后旧令牌仍然有效；现通过密码指纹使全部旧令牌立即失效。
13. 缺少用户自助修改密码入口；现已在侧边栏用户区域提供。
14. 失败登录没有审计；现已记录失败事件和尝试用户名。
15. Nginx 缺少登录限流和内容安全策略；现已增加登录限流、CSP、安全响应头，并为上传请求预留协议开销。
16. API 曾等待 Neo4j 健康后才启动，与“图谱故障时核心功能降级可用”冲突；现改为只等待服务启动。
17. Neo4j 浏览器端口曾暴露到宿主机；现已取消默认暴露，并修正健康检查密码传递方式。
18. Docker 示例环境曾把 `APP_ENV` 设置为 development，绕过生产密钥检查；现已改为 production。
19. 会话此前只保存消息，后续提问仍按单轮处理；现已增加结构化维修会话状态、有限历史组装、检查进度去重、故障切换隔离、显式重置边界和恢复收口。
20. PostgreSQL 曾依赖 `create_all` 和启动时临时补字段；公开发布版已建立 Alembic 初始迁移，并在 API 启动前自动升级。
21. API 健康接口曾在数据库异常时仍返回 HTTP 200，可能让编排系统误判就绪；现已拆分存活与就绪探针，并在数据库不可用时返回 503。
22. 登录仅依赖 Nginx 来源 IP 限流，无法抵御分布式尝试或绕过代理后的攻击；现已增加数据库级账号失败计数、限时锁定和管理员解锁。
23. 管理员只能创建用户，无法终止离职或异常账号权限；现已增加账号启停，并阻止停用自己或最后一个启用的管理员。
24. 生产启动曾无条件写入演示业务数据；现已改为默认关闭、仅显式启用的演示种子流程。
25. `.env.example` 中的上传大小设置没有传入 API 容器；现已补齐 Compose 变量映射。
26. 前后端版本号与 Changelog 不一致；现已统一为 0.2.0。
27. 文档去重仅依靠写入前查询，并发上传可能绕过；现已增加数据库唯一约束和失败文件清理。
28. 审计事件无法直接关联到一次 HTTP 请求；现已增加请求标识响应头和审计关联字段。
29. Web 端口固定为 8080，容易与本地环境冲突；现已支持通过 `WEB_PORT` 配置。
30. Dependabot 的 Docker 路径未覆盖实际 Dockerfile；现已分别覆盖前后端镜像定义。
