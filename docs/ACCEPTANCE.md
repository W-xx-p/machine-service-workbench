# 首版验收清单

## 功能验收

- 管理员能够登录、创建内部用户并查看审计。
- 管理员能够停用、启用和解锁账号；不能停用当前登录账号或最后一个启用的管理员。
- 未登录用户不能访问产品、资料、问答和管理接口。
- 能导入文本资料；完整 Docker 环境能解析 PDF、DOCX、XLSX、PPTX 和常见图片。
- 资料解析后仍处于待审核，未发布内容不会被问答检索。
- 审核员能够发布、驳回或废止资料和知识项。
- 能按机型查询产品参数、报警路径、备件核对条件和维修案例。
- 问答能返回来源、版本、适用机型、置信度和工程师确认标识。
- 同一会话的后续问题能继承机型、序列号、报警和现场反馈，并跳过已确认完成的检查步骤。
- 切换报警时旧检查进度不会串入新故障；清空上下文后旧消息不会重新恢复旧故障状态。
- 用户能够查看当前维修会话状态、清空上下文或开始新的故障会话。
- 未命中可靠知识时拒绝生成维修结论。

## 安全验收

- 修改所有默认口令，`APP_SECRET` 使用至少 32 字节随机值。
- 连续失败登录会触发持久化限时锁定，并产生失败、锁定、解锁审计记录。
- `/health/live` 只检查进程存活；`/health/ready` 在数据库不可用时返回 HTTP 503。
- 正式环境保持 `SEED_DEMO_DATA=false`，演示环境与企业数据环境分离。
- PostgreSQL 与 Neo4j 不向企业外网暴露端口。
- Nginx 使用企业证书启用 HTTPS，并设置文件上传限制。
- 测试越权、恶意文件、超大文件、提示词注入和敏感数据外发。
- 禁止把 `DEMO-*` 备件号用于采购，禁止把演示报警当作真实手册。
- 完成 PostgreSQL、Neo4j 和原始资料的备份恢复演练。

## 业务验收

- 选择一个成熟产品系列，准备至少 100 个真实售后问题作为盲测集。
- 分别统计检索命中率、来源正确率、机型适配正确率、拒答率和工程师采纳率。
- 高风险答案逐条由企业指定责任人签字验收。
- 只有当来源正确率和机型适配正确率达到企业设定门槛后，才扩大到其他产品系列。
