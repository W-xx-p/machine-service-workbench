# 机床售后技术支持工作台架构与业务流程

## 系统定位

机床售后技术支持工作台是面向单企业、私有化部署的数控机床售后知识协同与故障辅助系统。它独立运行，并通过文件或 API 与企业已有的 PLM、ERP、CRM、工单系统对接；它不承担库存、财务、派工、实时采集或设备控制。

## 数据职责

- PostgreSQL：用户与角色、产品主数据、资料元数据、审核状态、文档分块、消息记录、结构化维修会话状态、反馈和审计。
- pgvector：已发布资料分块的相似度检索；当前提供无需外部模型的本地特征哈希向量，企业可替换为批准的嵌入模型。
- Neo4j：产品系列、机型、子系统、报警、备件与维修案例关系。应用不接受模型自由生成的 Cypher，只运行固定、参数化模板。当前首条落地路径是“机型—换刀子系统—报警—待核对备件/相似案例”。
- 文件目录：原始资料。数据库只保存路径、校验值和解析结果。

生产环境默认只初始化首个管理员，不写入演示业务数据。演示产品、报警、备件与案例必须通过 `SEED_DEMO_DATA=true` 显式启用，并与企业数据环境分开使用。

## 运行与账号安全

- Nginx 对登录接口执行来源 IP 限流；数据库同时持久化失败次数和限时锁定状态，重启 API 不会绕过锁定。
- 管理员可停用、启用和解锁账号；停用后现有令牌在下一次请求时立即失效。
- 密码变更通过密码指纹使旧令牌立即失效，应用权限始终以数据库中的当前角色和状态为准。
- `/health/live` 用于判断 API 进程是否存活，`/health/ready` 用于判断数据库是否可服务；Docker 只在就绪检查通过后启动 Web 入口。
- 每次请求都会返回 `X-Request-ID`；业务审计自动保存同一标识，便于从用户报错定位到具体操作记录。

## 知识进入系统

1. 工程师上传说明书、报警手册、备件表或维修案例，并填写版本和适用机型。
2. 系统计算 SHA-256，阻止同一文件重复导入。
   数据库同时约束文件校验值以及“资料名称 + 版本”，避免并发上传绕过接口检查。
3. 文本资料直接解析；PDF、Office 和图片由 Docling 统一转为结构化文本。
4. 系统分块并生成检索向量，以保守规则提取报警码和备件号候选。
5. 所有候选知识初始为 `pending`，不能进入正式问答。
6. 审核人员核对来源、版本和适用范围后发布；旧版本可废止，记录保留在审计中。

## 一次故障辅助请求

1. 用户选择或输入机床型号，并描述报警码、现象和发生步骤。
2. 系统识别机型和报警码，并将它们与当前用户会话中保存的序列号、初始现象、已完成检查和现场反馈合并；缺少关键上下文时明确要求补充。
3. 后端匹配结构化报警，并通过 Neo4j 固定查询取得机型、子系统、待核对备件和相似案例的关联路径。
4. 图谱关联补全结构化候选，pgvector 使用“当前问题 + 结构化会话状态 + 最近有限轮用户描述”在同机型已发布资料中检索文本依据。
5. 返回未完成的后续检查、停止条件、数据边界、置信度、来源和关系路径；不会重复推荐本会话已确认完成的步骤。
6. 工程师反馈结果后，系统更新排查状态；切换报警时旧进度自动隔离，故障恢复时转为关闭记录提示。
7. 工程师作最终判断，并可对答案反馈；提问、上下文重置和反馈写入审计日志。

会话上下文与原始消息分表保存。最多使用最近 6 条用户描述辅助检索，避免历史无限增长；上下文只允许会话所有者或管理员访问。显式重置会记录消息边界，重置前的故障不会被后续问题重新继承。

当前图谱试点范围会在问答页和总览页明确展示。只有存在完整“机型—子系统—报警”主路径时才启用图谱补全；单独存在案例或备件关系不算已覆盖。未覆盖问题继续使用结构化数据与文档检索，并向用户显示降级说明。

## 大模型接口

`LLM_ENABLED`、`LLM_BASE_URL`、`LLM_API_KEY` 和 `LLM_MODEL` 是通用 OpenAI 兼容接口占位符。首版默认关闭，`LLMGateway.generate` 不会向外部发送数据。接入豆包、Kimi、GPT、DeepSeek 或本地 vLLM 前，应单独完成数据出境、提示词注入和输出审核评估。

## 已知边界

- 当前种子报警、备件和案例仅是演示数据，不能用于真实维修。
- 文档解析在 API 进程内执行；当单次资料量明显增大时，应增加受控任务队列，但不属于首版技术栈。
- PostgreSQL 结构由 Alembic 管理，容器启动时先升级到已审核版本；SQLite 的 `create_all` 仅用于隔离测试和轻量本地开发。
- 没有实现多租户、双活、实时设备采集、自动诊断、远程控制或自动参数修改。
- 当前令牌保存在浏览器本地存储中，适合受控内网首版；更高安全等级应改用企业 SSO/MFA 与安全 Cookie 会话。
